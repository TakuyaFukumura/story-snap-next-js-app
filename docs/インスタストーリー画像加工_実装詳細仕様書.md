# インスタストーリー画像加工アプリ 実装詳細仕様書

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 対象 | インスタストーリー専用画像加工MVP |
| 関連文書 | [仕様検討書](./インスタストーリー画像加工_仕様検討書.md) |
| 実装方式 | Next.js App Router + React + TypeScript |
| データ保存 | 画像・編集情報ともにブラウザ内のみ |

## 2. 実装方針

- 編集ページはClient Componentとして実装する。
- 原画像を変更せず、`ImageBitmap`または`HTMLImageElement`と編集状態から毎回Canvasを再描画する。
- 表示用Canvasと保存用Canvasは同じ描画関数を共有し、プレビューと出力の差異を防ぐ。
- サーバーAPI、データベース、Cookie、localStorage、IndexedDBはMVPでは使用しない。
- Object URLは画像の読み込み完了後または画像破棄時に必ず`URL.revokeObjectURL`する。

## 3. 定数・入力仕様

```ts
const CANVAS_WIDTH = 1080;
const CANVAS_HEIGHT = 1920;
const ASPECT_RATIO = 9 / 16;
const MAX_FILE_SIZE = 10 * 1024 * 1024;
const ACCEPTED_MIME_TYPES = ["image/jpeg", "image/png", "image/webp"];
const MAX_SOURCE_PIXELS = 40_000_000;
```

- 出力キャンバスは常に1080 x 1920 pxとする。
- 原画像が1080 x 1920未満の場合も、Canvasの出力サイズは固定する。ただし品質劣化を警告する。
- デコード後の総画素数が`MAX_SOURCE_PIXELS`を超える画像は、メモリ保護のため拒否する。
- MIME typeだけでなく、ブラウザで画像デコードできることを検証する。
- SVG、動画、アニメーション画像、HEICは対象外とする。

## 4. 型定義

```ts
type EditorPhase =
  | "empty"
  | "loading"
  | "detecting"
  | "editing"
  | "exporting"
  | "error";

type Point = { x: number; y: number };
type Rect = { x: number; y: number; width: number; height: number };

type Transform = {
  scale: number;
  offset: Point;
};

type MosaicStrength = "weak" | "medium" | "strong";

type MosaicRegion = {
  id: string;
  source: "face" | "manual";
  rect: Rect; // 原画像上の座標
  selected: boolean;
};

type EditorState = {
  phase: EditorPhase;
  sourceImage: HTMLImageElement | ImageBitmap | null;
  sourceSize: { width: number; height: number } | null;
  transform: Transform;
  faces: MosaicRegion[];
  strength: MosaicStrength;
  outputFormat: "image/jpeg" | "image/png";
  errorMessage: string | null;
};
```

- モザイク領域は原画像座標で保持し、表示倍率が変わっても領域がずれないようにする。
- `sourceImage`はReactの状態へ直接シリアライズせず、必要に応じてrefで保持する。
- 編集状態の初期値は`strength: "medium"`、`outputFormat: "image/jpeg"`とする。

## 5. 状態遷移

```text
empty
  -> loading       ファイル選択
loading
  -> detecting     画像デコード成功
  -> error         読み込み失敗
detecting
  -> editing       顔検出完了（0件を含む）
  -> error         検出処理の致命的失敗
editing
  -> editing       移動、ズーム、領域選択、強度変更
  -> exporting     保存開始
  -> empty         リセット
exporting
  -> editing       保存完了または保存失敗から復帰
error
  -> empty         閉じる、または新しい画像を選択
```

- `loading`、`detecting`、`exporting`中は編集操作と保存ボタンを無効化する。
- 顔検出の失敗は画像編集を継続できる非致命エラーとして扱い、手動モザイクを使用可能にする。
- 新しいファイルを選択した場合は、旧画像、顔領域、変換状態、エラーをすべて破棄する。

## 6. コンポーネント構成

```text
app/page.tsx
└─ StoryEditor
   ├─ ImageUploader
   ├─ EditorCanvas
   ├─ FaceRegionList
   ├─ MosaicControls
   ├─ ExportControls
   └─ StatusMessage
```

### `ImageUploader`

- `accept="image/jpeg,image/png,image/webp"`を指定する。
- inputの`change`、ドラッグ＆ドロップ、モバイルのタップ選択を同じ検証関数へ渡す。
- 選択後に同一ファイルを再選択できるよう、処理完了時にinput valueをクリアする。

### `EditorCanvas`

- 表示サイズは親要素の幅に合わせ、CSSで9:16を維持する。
- Canvasの内部解像度は表示倍率にかかわらず1080 x 1920とする。
- Pointer Eventsを使用し、マウス、タッチ、ペンを同じ経路で扱う。
- 1本指のドラッグは画像移動、ピンチはズーム、矩形選択モードでは領域追加として扱う。
- `touch-action: none`をCanvasに適用し、ブラウザのスクロール・ズーム介入を防ぐ。

### `FaceRegionList`

- 検出顔の番号、選択状態、モザイク適用状態を表示する。
- Canvas上の矩形クリックとリスト上のチェック操作を双方向に同期する。
- 顔が0件の場合は「顔を検出できませんでした。手動で領域を追加できます。」と表示する。

### `MosaicControls`

- 強度はラジオボタンで「弱・中・強」を表示し、現在値を明示する。
- 「手動で追加」モードと「選択を解除」操作を提供する。

### `ExportControls`

- JPEG/PNGの形式選択、保存、リセットを提供する。
- 保存中はボタンラベルを「保存中…」に変更する。

## 7. 画像読み込みと初期変換

1. ファイルが1つであることを確認する。
2. サイズとMIME typeを検証する。
3. Object URLを生成し、画像をデコードする。
4. EXIFの向きがブラウザのデコード結果へ反映されない環境を考慮し、必要に応じて`createImageBitmap(file, { imageOrientation: "from-image" })`を使用する。
5. デコード後のサイズと画素数を検証する。
6. `cover`になる最小スケールを次で求める。

```ts
const coverScale = Math.max(
  CANVAS_WIDTH / sourceWidth,
  CANVAS_HEIGHT / sourceHeight,
);
```

7. 初期`transform.scale`は`coverScale`、`offset`は中央配置とする。
8. 顔検出は変換前の原画像に対して実行する。

## 8. Canvas描画仕様

描画関数は次の順序で実行する。

1. Canvasをクリアする。
2. 背景色を白で塗る。
3. 原画像を`transform.scale`と`transform.offset`で描画する。
4. 選択された各モザイク領域について、原画像座標の矩形をCanvas座標へ変換する。
5. 変換後の矩形をCanvas境界へクリップする。
6. 矩形内をモザイク処理する。
7. 編集中のみ、選択状態の枠線と操作用オーバーレイを描画する。保存時は描画しない。

```ts
const toCanvasRect = (rect: Rect, transform: Transform): Rect => ({
  x: rect.x * transform.scale + transform.offset.x,
  y: rect.y * transform.scale + transform.offset.y,
  width: rect.width * transform.scale,
  height: rect.height * transform.scale,
});
```

- 表示CanvasのCSSサイズと内部解像度の差は、Pointer座標を内部Canvas座標へ正規化して吸収する。
- 画像移動は、画像の外周がCanvas内に現れない範囲に`offset`をクランプする。
- ズーム倍率は`coverScale`以上、`coverScale * 4`以下とする。

## 9. 顔検出仕様

- ブラウザ実行可能な顔検出ライブラリを採用し、モデルは初回利用時に読み込む。
- ライブラリ選定時は、商用利用可能なライセンス、モデルの配布条件、gzip後のサイズ、Safari対応を確認する。
- 検出結果は原画像のピクセル座標へ正規化する。
- 信頼度が設定閾値未満の結果は表示しない。初期閾値は0.6とする。
- 検出領域は上下左右に10%拡張する。ただし原画像の境界を超えない。
- 検出順は検出器の順序に依存させず、左上座標（y、x）で安定ソートする。
- 検出処理がタイムアウトまたはモデル読み込みに失敗した場合は、編集画面へ進めて手動領域追加を有効にする。

## 10. 手動モザイク仕様

- 手動モザイクはMVPに含める。
- 「手動で追加」モード中にCanvasをドラッグして矩形を作成する。
- 矩形の最小サイズは表示上20 x 20 px相当とする。
- 作成時に原画像座標へ変換し、画像境界へクランプする。
- 作成した領域は初期状態で選択済みとする。
- 選択領域はタップで選択解除・再選択でき、削除操作で一覧から除去する。

## 11. モザイクアルゴリズム

強度ごとのブロックサイズは以下とする。

| 強度 | ブロックサイズ | 用途 |
| --- | ---: | --- |
| 弱 | 12 px | 軽い判別抑制 |
| 中 | 24 px | 標準 |
| 強 | 40 px | 強い秘匿 |

処理対象領域は、Canvasへ描画した後の領域を一時Canvasへコピーし、次の手順で処理する。

1. 対象領域をブロックサイズ単位に分割する。
2. 各ブロックの中央色または平均色を1色取得する。
3. ブロック全体を取得色で塗りつぶす。
4. 対象領域の外側へ処理が漏れないよう、矩形クリップを解除せずに描画する。

境界の顔が残らないよう、検出領域の拡張後にさらに2 px相当の安全余白を追加する。

## 12. 保存仕様

- 保存開始時に最新状態で編集用オーバーレイなしのCanvasを描画する。
- JPEGは`canvas.toBlob(callback, "image/jpeg", 0.92)`、PNGは`canvas.toBlob(callback, "image/png")`を使用する。
- Blobがnullの場合は保存失敗としてユーザーへ通知し、編集状態を維持する。
- `URL.createObjectURL(blob)`でダウンロードリンクを生成し、クリック後にURLを破棄する。
- ファイル名は`story-snap-YYYYMMDD-HHmmss.{jpg|png}`とする。日時は端末のローカル時刻を使用する。
- 保存画像にはメタデータ、顔検出結果、元ファイル名を埋め込まない。

## 13. エラーコードと表示文言

| コード | 条件 | 表示文言 |
| --- | --- | --- |
| `EMPTY_FILE` | ファイル未選択 | 画像を選択してください。 |
| `UNSUPPORTED_TYPE` | 対応外形式 | JPEG、PNG、WebPの画像を選択してください。 |
| `FILE_TOO_LARGE` | 10 MB超過 | 画像は10 MB以下にしてください。 |
| `DECODE_FAILED` | 画像破損・デコード失敗 | 画像を読み込めませんでした。別の画像を選択してください。 |
| `IMAGE_TOO_LARGE` | 総画素数超過 | 解像度が高すぎます。小さい画像を選択してください。 |
| `FACE_MODEL_FAILED` | モデル読み込み失敗 | 顔検出を利用できません。手動でモザイク領域を追加できます。 |
| `EXPORT_FAILED` | Blob生成失敗 | 画像を保存できませんでした。もう一度お試しください。 |

- エラー文言は`aria-live="polite"`領域へ出力する。
- 致命的でない顔検出エラーは編集画面をエラー画面へ遷移させない。

## 14. アクセシビリティ・レスポンシブ対応

- 主要操作はCanvas上の操作だけに依存させず、ボタン、ラジオ、リストでも実行可能にする。
- すべての操作要素に日本語のlabelを付ける。
- キーボードフォーカスを可視化する。
- 編集Canvasには「9:16画像編集領域。選択した顔にモザイクを適用します。」のラベルを付ける。
- 画面幅320 px以上で横スクロールを発生させない。
- 操作パネルはモバイルではCanvas下、デスクトップではCanvas横へ配置する。

## 15. テスト仕様

### 単体テスト

- MIME type、ファイルサイズ、画素数の入力検証
- `coverScale`、座標変換、境界クランプ
- モザイク領域の10%拡張とCanvas境界クリップ
- 強度ごとのブロックサイズ選択
- ファイル名と出力形式の決定
- 画像読み込み・顔検出・保存の状態遷移

### コンポーネントテスト

- ファイル選択後に編集Canvasが表示される
- 不正ファイルでエラー文言が表示される
- 検出顔の選択と解除が一覧・Canvasで同期する
- 強度変更が再描画を発生させる
- 顔0件でも手動追加ボタンが利用できる
- 保存中に保存ボタンが無効化される

### 手動確認

- iOS SafariとAndroid Chromeで、タップ、ドラッグ、ピンチ、保存を確認する。
- 縦長、横長、正方形、EXIF回転画像、10 MB境界付近の画像を確認する。
- 顔が複数ある画像、顔がない画像、部分的に画面外の顔を確認する。
- 原画像を外部通信、localStorage、IndexedDBへ保存していないことを確認する。

## 16. 実装順序

1. 型定義、定数、状態管理、ファイル検証を実装する。
2. 画像読み込みと9:16 Canvas描画を実装する。
3. 移動、ズーム、Pointer Eventsを実装する。
4. 顔検出アダプターと顔領域選択を実装する。
5. 手動モザイクとモザイク描画を実装する。
6. 保存形式選択とダウンロードを実装する。
7. エラー表示、アクセシビリティ、レスポンシブ調整を実装する。
8. テストと主要ブラウザでの手動確認を行う。
