# 顔検出できない問題

## 事象

画像を選択すると顔検出処理へ進むが、顔が検出されず、手動モザイクへの切り替えを促す状態になる。

## 調査日・対象

- 調査日: 2026-09-02
- 対象ブランチ: `investigate-face-detection`
- 対象実装: `src/app/components/StoryEditor.tsx`
- 対象ライブラリ: `@mediapipe/tasks-vision` 1.0.1

## 現在の処理フロー

1. 画像を `Image.decode()` で読み込む。
2. `FilesetResolver.forVisionTasks(WASM_URL)` でMediaPipeのWASMランタイムを初期化する。
3. `FaceDetector.createFromOptions()` でモデルを読み込む。
4. `detector.detect(image)` の結果から検出矩形を作り、モザイク範囲として表示する。
5. 1〜3のいずれかで例外が発生すると、`catch`で例外内容を捨てて `setRegions([])` と「顔検出を利用できません。」を設定する。

## 確認できた原因

### WASM URLのバージョン不整合（修正済み）

依存関係と実装で参照するバージョンが一致していない。

| 対象 | 現在値 | 確認結果 |
| --- | --- | --- |
| npm依存 | `@mediapipe/tasks-vision: ^1.0.1` | `node_modules`の実体は `1.0.1` |
| WASM URL | `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.22/wasm` | `vision_wasm_internal.js` がHTTP 404 |
| 同一依存バージョンのWASM URL | `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@1.0.1/wasm/vision_wasm_internal.js` | HTTP 200 |
| モデル URL | BlazeFace Short Range float16 v1 | HTTP 200 |

したがって、現状はWASMランタイムの取得に失敗し、`FaceDetector.createFromOptions()`まで到達できない可能性が高かった。`WASM_URL`をnpm依存と同じ1.0.1へ合わせる修正を実施した。

### 原因を画面から判別できない

`detectFaces`の`catch`が例外を記録せず、ネットワークエラー、WASM初期化エラー、GPU非対応、モデルエラーを同じメッセージに変換している。そのため、利用者の症状だけでは原因を特定できない。

## 追加で確認が必要な点

第一原因を修正した後、次をブラウザ実機で確認する。

- DevToolsのNetworkでWASMのJavaScript/WASMファイルが200で取得されること
- ConsoleにMediaPipe初期化エラーが出ないこと
- GPU非対応環境で `delegate: "GPU"` が失敗しないこと
- 正面・斜め・小さい顔を含むJPEG/PNG/WebPで検出できること
- 顔がない画像では誤検出せず、手動範囲追加へ進めること
- 画像を連続して選択した場合に、前回の検出結果が残らないこと

## ネクストアクション

### P0: URLのバージョンを揃える（実施済み）

`WASM_URL`をインストール済みライブラリの1.0.1と一致させた。CDNを使い続ける場合は、モデル・WASM・JavaScript APIのバージョンを固定し、依存更新時に同時更新する。

### P1: 初期化失敗の切り分けを可能にする（実施済み）

- `catch`で元の例外を `console.error` に記録する（画像データや個人情報は記録しない）。
- `GPU` delegate失敗時は、`CPU` delegateで一度だけ再初期化して再試行する。
- WASM URL、モデルURL、依存バージョンの到達性をCIまたは起動前チェックで検知する。

### P1: 配信方式を検討する

外部CDN障害やCSP・ネットワーク制限の影響を避けるため、WASMとモデルを`public/`へ同梱する案を比較する。採用する場合はファイルサイズ、ライセンス、更新手順を確認する。

### P2: 回帰テストを追加する

MediaPipeをモックし、次をテストする。

- 初期化後に検出矩形が`regions`へ変換される
- 初期化失敗時に手動編集へ進める
- GPU失敗後にCPUへフォールバックする
- 検出結果が空の場合に適切な表示になる

## 修正の受け入れ条件

- 対象ブラウザで画像選択後、WASMとモデルが正常に読み込まれる。
- 顔を含むサンプル画像で、顔ごとのモザイク範囲が自動選択される。
- GPUが利用できない環境でもCPUフォールバックで検出できる。
- 顔検出に失敗した場合、原因を開発者がConsoleで追跡できる。
- 顔検出が利用できない場合も、既存の手動モザイク機能を妨げない。

## 暫定回避策

現状でも「手動で範囲を追加」から加工を継続できる。ただし、自動顔検出を利用するには、まずP0のWASM URL修正が必要である。
